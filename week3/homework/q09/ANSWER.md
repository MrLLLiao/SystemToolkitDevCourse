# 练习9: 从零开始"氛围编程"（Vibe Coding）一个小应用，不手动写一行代码

## 练习要求
从零开始氛围编程一个小应用，不要手动编写一行代码。

## 什么是"氛围编程"（Vibe Coding）
Vibe Coding = 用自然语言把产品需求直接"喂"给 AI，让 AI 一次性产出完整可运行的应用，
人不再逐行手写代码，而是负责"说清楚要什么 + 验收结果"。
本次演示：我只写了一段需求提示词（`prompt.md`），然后由 AI 端到端产出整个应用（`index.html`），
我没有手工改任何一行应用代码——应用代码就是 AI 的一次性输出。

## 我给 AI 的提示词（prompt.md 全文见该文件）
核心需求一句话概括：**单文件、零依赖的"番茄钟 + 待办"Web 小工具**。
并显式给出：倒计时 25/45/60 分钟可切换、开始/暂停/重置、结束提示音(Web Audio)、
待办 localStorage 持久化、绿色现代 UI、功能正确即可不追求完美工程。

## AI 一次性产出的应用（index.html）
一个单文件 HTML（内嵌 CSS + JS，8.5 KB），功能全部兑现：
- 番茄钟：默认 25:00，大字倒计时；开始/暂停/重置；25/45/60 分钟切换；
- 倒计时结束：Web Audio 提示音 + "时间到！休息一下吧"；
- 待办清单：添加/勾选/删除，localStorage 持久化；
- 刷新后恢复上次计时状态（localStorage）；
- 无任何外部依赖（无 CDN、无框架、无外链）。

## 对氛围编程的反思（真实体会）
**优点**：
1. **门槛极低**：不用了解框架/构建工具，一句话就能得到能跑的应用；
2. **原型速度极快**：从"想法"到"可运行 demo"只需一个提示词（本次 8.5KB 应用一次性产出）；
3. **适合个人工具/一次性脚本**：不用维护工程结构，功能正确就够。

**局限与坑**：
1. **"看起来对"不等于"真对"**：模型自信地生成代码，但不保证逻辑无 bug（比如计时器边界、localStorage 异常）；
2. **无自动化测试**：vibe 产出通常没测试，改起来没有安全网——规模一大就失控；
3. **难排错**：你不懂它写了什么，出 bug 时只能继续"用嘴修"，可能越修越糟；
4. **工程性差**：单文件、无版本化依赖、无类型，不适合协作或长期演进。

**什么时候用 / 不用**：
- 用：个人小工具、原型验证、教学演示、一次性自动化；
- 不用：核心业务、需要长期维护/多人协作/严格测试的项目（那里"手动+AI 辅助"比"全 vibe"更稳）。

## 一句话总结
氛围编程把"写代码"变成"描述需求 + 验收"，极大降低创作门槛，但把质量责任完全交给了模型；
最好的用法是把它当"超级原型工具"，而非替代工程纪律。
