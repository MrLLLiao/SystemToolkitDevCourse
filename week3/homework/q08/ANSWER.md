## 核心结论（浏览一个陌生代码库应该得到的"地图"）
**tenacity = 策略对象组合 + 一个状态机控制器**
1. **入口**：`@retry(stop=…, wait=…, retry=…)` 工厂（__init__.py:736），支持 `@retry` 与 `@retry()`；
2. **调用链**：`retry()` 按函数是否协程选 `AsyncRetrying/TornadoRetrying/Retrying` → `wraps(f)`
   生成包装函数 → `Retrying.__call__` 的 while 循环；
3. **核心机制**：`iter()` 返回哨兵 `DoAttempt`（让调用方执行 fn 并记录 outcome）或 `DoSleep`
   （睡完继续）——把"执行函数"与"休眠"交回调用方，同步/异步共用一套逻辑；
4. **数据流**：`RetryCallState` 贯穿每次尝试；`statistics` 用 `threading.local()` 隔离线程；
5. **模块分工**：`retry.py`(要不要重试)/`stop.py`(何时停)/`wait.py`(睡多久)/`before·after·before_sleep`(钩子)。

## 智能体浏览陌生代码库的"方法论"（本次实际用到的套路）
1. **先轮廓后细节**：`git ls-files | wc -l`、目录树、`wc -l`——判断规模与模块，再决定精读哪里；
2. **从公开 API 反推设计**：`__init__.py` 的 import 与 `__all__` 揭示"面向用户的组合点"；
3. **类图/函数清单快速摸底**：`grep -E "^(class|def)"` 一屏看清所有类型与职责边界；
4. **追"入口 → 核心循环"**：从装饰器一路跟到 `Retrying.__call__` 与 `iter()` 动作流水线；
5. **找反例/边界**：`enabled=False`、`TryAgain`、成功不 sleep 等分支——避免把"实现了"当"总会发生"；
6. **用测试目录当"可执行文档"**：tests 与被测模块一一对应；
7. **动手运行验证**：写最小 demo 证明对关键结论的理解（这是最强的核验）。

## 收获
- 陌生代码库的浏览不是"从头读到尾"，而是"规模判断 → 公开面 → 核心闭环 → 边界 → 验证"；
- 智能体的价值在于能同时持有"类图 + 调用链 + 数据流"多张图，并把结论落到可运行证据上；
- 读第三方库源码是理解一门语言生态最快的方式之一（tenacity 的设计对我后续写健壮脚本有直接参考价值）。
