# 练习1: `--` 特殊参数与以 "-" 开头的文件

## 练习要求
运行 `touch -- -myfile`，然后在不使用 `--` 的情况下把它删掉。

## 核心概念：`--` 的作用
`--` 是一个特殊的"选项终止符"（end-of-options）。它告诉命令行程序：**后面出现的内容不再解析为选项（flag），一律当作位置参数（positional argument）处理**。常见的命令形式如：

```
cmd -- --notaflag
```

意思是：`cmd` 执行时遇到 `--` 后，`--notaflag` 被当作普通参数而非选项。

## 实验过程与结果

| 步骤 | 命令 | 结果 |
|------|------|------|
| 1 | `touch -myfile` | 报错 `error: unexpected argument '-y' found`——`-m` 被拆成多个选项解析失败 |
| 2 | `touch -- -myfile` | 成功创建名为 `-myfile` 的文件 |
| 3 | `rm ./-myfile` | **成功删除，全程没有使用 `--`** |
| 4 | `rm -myfile`（对比） | 报错 `rm: invalid option -- 'm'`，提示 `Try 'rm ./-myfile'` |
| 5 | `rm -- -myfile` | 用 `--` 也能删除 |

## 不使用 `--` 删除的技巧
把文件名改成带路径的形式即可绕过选项解析：

```bash
rm ./-myfile      # ./ 前缀让 rm 把它当成路径而非选项
rm /path/to/-myfile
```

因为选项解析只针对"以 `-` 开头的参数"；当参数是 `./-myfile`（以 `./` 开头）时，不再被视为选项，从而不需要 `--`。

## 总结
- `--` 用来安全处理以 `-` 开头的文件名（如 `-myfile`、`--help.txt`）。
- 不用 `--` 的替代方案：加路径前缀（`./`、绝对路径）使参数不以 `-` 开头。
- 实际工作中处理 `-` 开头文件时，两者均可，但 `--` 更通用、可读性更好。
