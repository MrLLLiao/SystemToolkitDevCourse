# 练习7: 用 wait 等待后台任务完成

## 练习要求
假设你不想在某个进程完成之前启动另一个进程，限制条件是 `sleep 60 &`。一种实现方式是使用 `wait`：启动 sleep，然后让一个 `ls` 等到后台进程结束后再执行。

## 核心用法
```bash
sleep 60 &
wait $!      # 等刚启动的那个后台任务结束（$! 是其 pid）
ls           # 只有 sleep 结束后才会执行
```

`wait` 的两种形式：
- `wait $PID`：等待指定后台子进程，返回它的退出码；
- `wait`（不带参数）：等待**当前 shell 的所有后台子进程**。

## 实验设计
演示脚本将讲义中的 `sleep 60` 换成可配置的 `SLEEP_SECS`（默认 3 秒）以节省演示时间，机制完全相同：
1. `sleep 3 &` 后台启动，记录 pid；
2. `wait $PID` 阻塞；
3. 用 `date +%s` 计时，证明 `wait` 确实阻塞了约 3 秒，之后才执行 `ls`；
4. 再演示不带参数的 `wait` 会等待所有后台任务（等最慢的结束）。

## 为什么需要 wait
- 后台任务与当前 shell 并行执行；`wait` 提供显式同步点，保证后续命令依赖的后台结果已就绪。
- 这在"启动耗时任务 → 汇总其输出"的自动化脚本中很常见。

## 局限（引出下一个练习）
`wait` 只能等待**当前 shell 的子进程**。如果任务是在另一个 bash 会话（或子 shell）里启动的，`wait` 无效——这就需要用 `pidwait` 之类的轮询函数（见 q08）。
